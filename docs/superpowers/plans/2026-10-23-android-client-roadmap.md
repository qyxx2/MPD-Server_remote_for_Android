# MPD-Server 安卓原生客户端初步实现路线图

> **状态：初步路线图，非权威规格，暂不作为直接实施授权。**
> 本文只概括建议阶段、依赖关系和主要风险。正式 UI/行为规格尚未冻结，后续应根据讨论结果另行制定权威规格和可执行的分批计划。

## 目标

为 `MPD-Server` 开发独立的 Android 原生客户端，使用 Kotlin 与 Jetpack Compose 编写全部界面，不使用 WebView 套壳。优先复用后端现有 HTTP API、WebSocket 协议及 Web 客户端已经形成的播放控制、状态同步、队列和异常恢复语义，避免重复实现后端业务。

## 建议架构

```text
Jetpack Compose 页面
        ↓
ViewModel / StateFlow
        ↓
共享状态仓库与操作协调层
        ↓
HTTP API + WebSocket
        ↓
MPD-Server（现有后端）
        ↓
MPD（实际播放与音频输出）
```

建议采用单一共享的播放状态来源，供全屏播放器、迷你播放器、主页及状态提示共同读取。具体依赖库和模块边界仍待规格阶段确定；Kotlin、Jetpack Compose 是既定方向，ViewModel、Coroutines/Flow、OkHttp、Kotlin Serialization、Navigation Compose 与 DataStore 可作为候选实现。

## 初步阶段

### 0. 现有合同核对与规格准备

- 实施前重新核对 `MPD-Server` 的目标分支 HEAD、API DTO、WebSocket 消息与 Web 播放相关代码，避免路线图基于过期实现。
- 整理接口映射、播放控制语义、队列身份、状态字段、错误与恢复行为。
- 单独制定并确认权威规格：页面职责和布局、迷你播放器行为、状态分类与优先级、状态环视觉及设置项。本文不提前冻结这些细节。

### 1. Android 项目骨架

- 建立可构建的原生 Kotlin/Compose 项目、基础导航和主题。
- 形成清晰的网络、模型、状态和页面职责边界；建立 DTO 解析及基本单元测试入口。
- 不在此阶段重做后端，也不引入独立的本地播放引擎。

### 2. 网络层与共享实时状态

- 对接 `GET /api/state` 和 WebSocket `/api/realtime`，实现初始快照、失效通知、状态刷新、断线重连与读取错误反馈。
- 保留 `epoch`、`sequence`、资源修订版本及状态新鲜度等保护，避免旧状态覆盖新状态。
- 实现统一写操作管理：使用后端要求的 `Idempotency-Key`，区分明确失败与结果未知，并沿用原操作恢复/重新读取的语义。
- 先通过 Mock 与协议测试覆盖断线、乱序、超时和未知结果，再接入实际服务验证。

### 3. 原生应用壳与导航

- 建立持久的 AppBar、内容区域和四个一级入口：主页、搜索、库、设置。
- 预留独立的全屏正在播放页面；页面切换不重复建立实时连接，也不丢弃尚未解决的操作状态。
- 根据正式规格确定页面切换、系统安全区域和不同屏幕尺寸下的布局规则。

### 4. 全屏播放器与队列

- 用 Compose 实现封面/歌词切换、歌曲信息、音频信息、进度和播放控制。
- 参考现有 Web 歌词解析、自动跟随、手动滚动及 seek 行为，并依据真实播放观察更新界面。
- 实现队列展示和现有支持的操作，包括播放指定项目、插入下一首、加入队列、移动、删除及保存队列等。
- 保留队列项目身份和重复曲目语义，不以 URI 猜测队列项目身份。

### 5. 迷你播放器与其余页面

- 将迷你播放器接入同一共享播放状态；在主页、搜索、库三个一级页面常驻显示，点击进入全屏正在播放页面。
- 实现搜索结果及分类跳转、曲库浏览、收藏/播放列表，以及现有设置 API 对应的连接和输出信息。
- 设置页同时容纳安卓客户端本地配置；客户端专属配置保存于本地，不为其无必要地增加后端接口。

### 6. 应用内全局状态环

- 仅在 **MPD-Server 安卓应用内部**显示全局状态环，覆盖应用自己的页面；不实现跨应用悬浮窗，不申请悬浮窗权限。
- 使用统一的活动/状态模型驱动状态颜色与旋转动画，避免每个页面自行判断状态。
- 在设置中提供规格确认后的圆环尺寸、位置偏移、线宽等参数，并验证其在目标手机挖孔与状态栏布局下的可调节性。
- 点击状态提示可打开统一详情，呈现具体活动或异常，并提供后端现有语义允许的重新读取或重试操作。

### 7. 集成验证与界面打磨

- 对照 Web 端核验关键行为，而不是只核验截图：播放/暂停、切歌、seek、队列操作、歌词、收藏及设置。
- 覆盖断线重连、乱序/过期状态、操作结果未知、服务端错误、曲库同步和输出状态异常。
- 在实际 Android 设备上调整全屏比例、迷你播放器和导航栏占位、歌词滚动、动画及状态环位置。
- 完成构建、核心单元测试、网络/状态协议测试和端到端人工验收后，再考虑发布准备。

## 全程约束

- MPD-Server 保持实际播放与业务状态的权威性；安卓端不直接控制 MPD，也不负责解码/输出音乐。
- 现有 HTTP API 与 WebSocket 优先复用。只有证实现有接口无法满足已确认需求时，才单独提出后端改动及其影响。
- 不把请求已发出、HTTP 成功或本地按钮点击等同于实际播放状态已确认。
- 页面、迷你播放器和状态环共享同一套状态与活动数据，避免多份独立状态互相冲突。
- UI 比例、具体颜色/动画、状态优先级、依赖版本和详细测试门槛均尚未在权威规格中冻结。

## 开始正式实施前需要确认

1. 权威 UI/行为规格以及 Web 与 Android 之间必须保持一致的行为清单。
2. Android 项目的最低系统版本、构建环境和依赖版本。
3. 四个一级页面的具体职责，以及首页与全屏播放器之间的关系。
4. 状态环所使用的状态分级、优先级、颜色、动画和可配置参数范围。
5. 每个阶段的详细范围、测试门槛和验收方式。
