# Task 5 单曲操作菜单呈现规格

## 意图
让 Home、Search、Library、专辑成员等普通单曲入口共用的操作菜单在视觉上跟随当前条目，减少菜单与触发歌曲之间的空间错位，并提高菜单文字和动作的辨识度。

## 目标
- 普通单曲菜单以触发条目为定位锚点，菜单整体中心与条目中心对齐；接近窗口边缘时安全夹紧，避免菜单超出可视区域。
- 所有选项左对齐，共用图标列与文字起点。
- 菜单宽度由最长选项文字及固定图标/间距/内边距自然决定，不按屏幕宽度拉伸。
- 菜单使用白色半透明背景，文字保持高对比度；圆角和阴影轻量，不制造厚重浮层。
- 每个动作提供与其含义一致、笔画风格统一的图标。
- 保留外部点击关闭、返回键关闭、条目可用性 gating、收藏状态和既有 MutationCoordinator 行为。

## 范围与非目标
- 覆盖 SongActionMenu 的所有调用点：Home 中无专辑 ID 的单曲卡片、歌曲列表、专辑成员和搜索/收藏/歌单等复用歌曲行。
- 不覆盖全屏正在播放页面。
- Queue occurrence 菜单继续使用其 queue-item 身份和现有操作，不替换成普通 Song 菜单。
- 不修改 Web/API、服务端队列、播放状态权威来源、收藏写入流程或数据缓存。

## 方案
- 方案 A：继续使用 Material DropdownMenu，仅调整 offset。其默认锚点策略以菜单边缘为主，难以让菜单在不同菜单高度/屏幕边缘下稳定围绕条目中心显示。
- 方案 B：使用 Compose Popup 与自定义 PopupPositionProvider，以条目完整 bounds 计算菜单中心并夹紧到窗口边界；菜单内容使用 intrinsic width。选用此方案，定位行为明确，且可继续使用同一共享单曲菜单入口。
- 方案 C：使用居中 Dialog。它不随当前条目定位，无法满足需求。

## 实现约束
- 菜单左侧固定图标列，所有文字共享左边界；内容列以最长标签决定右侧边界。
- 背景 Color.White alpha 约 0.94；文字使用深色不透明色。
- 圆角约 18dp，阴影约 7dp；不添加大面积遮罩。
- 播放、下一首、加入队列、收藏分别显示简洁线性/实心图标；禁用状态沿用统一透明度处理。
