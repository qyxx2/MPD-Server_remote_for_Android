## 1. 目标与产品定位

建立 MPD-Server 的独立原生 Android 客户端。客户端是服务端的遥控器与状态展示端，目标是在手机纵向场景下提供符合 Android 使用习惯、视觉精致、布局稳定、动画克制流畅的体验，并尽量复用现有后端接口与已验证业务行为。

Android UI **不以复制 Web 页面布局为目标**。Web 源码用于核对可复用的 API 调用、DTO、业务操作语义、状态同步、错误恢复和已有领域行为；页面信息架构、空间利用、导航与视觉设计以本文冻结的 Android 规则为准。

成功标准：
- 在参考手机竖屏和其他常见手机竖屏下，页面层级清晰，充分利用纵向空间，滚动、系统安全区、软键盘和字体缩放不造成控件遮挡或状态误导。
- 四个一级入口与迷你播放器始终遵循统一的应用壳；完整播放控制只存在于全屏正在播放页面。
- 播放、Queue、曲库、歌单、收藏、播放观察与恢复行为遵守现有服务端合同，不形成第二套业务权威。
- App 内播放控件、迷你播放器、状态环、系统媒体控件与当前共享状态一致，不因页面切换或进入后台产生互相矛盾的状态。
- 工程可通过标准 Gradle 命令构建、测试，并在 CI 生成 APK 构建产物。

## 3. 平台范围与设备约束

- **最低系统版本：** Android 8.0（API 26）。
- **目标形态：** 手机纵向单列界面。参考设备原始分辨率为 2800 × 1260，按手机纵向使用；核心适配基准为至少 392dp 的逻辑宽度。
- **其他手机：** 同一套单列 Compose 组件适配其他手机竖屏，包括更窄的可用宽度、更短的高度、系统字体缩放和不同系统栏 inset。
- **不在首期支持范围：** 平板专属布局、横屏双栏布局、桌面式多窗工作区及为宽屏设计的第二套导航。
- 布局以 dp、sp、WindowInsets 和实际可用窗口尺寸为依据，不把 1260/2800 等物理像素值直接写成 UI 尺寸。首期按竖屏设计，不为未支持的横屏建立另一套信息架构。
- 应用栏保持紧凑，不能用过高标题区挤压内容；页面正文尽可能使用剩余纵向空间。迷你播放器与底部导航在正常布局流中分配固定角色，不覆盖或压住正文。
- 对短屏、软键盘、显示缩放和大字体等情况，优先允许正文区域滚动和合理省略；不得关闭系统字体缩放、压缩到不可读或遮挡关键操作。

## 4. 技术栈与工程基线

### 4.1 已确定技术方向

| 层级 | 技术选择 | 约束与用途 |
|---|---|---|
| 语言 | Kotlin | 主业务和 UI 语言；不以 Java 为主要实现语言 |
| 构建 | Gradle Wrapper + Gradle Kotlin DSL + Android Gradle Plugin | 标准 Android 工程，可在 Android Studio、命令行和 CI 构建；不依赖 CodeAssist 专用的非 Gradle 构建流程 |
| UI | Jetpack Compose + Material 3 | 全部应用 UI 使用原生 Compose；不得用 WebView 包装现有网页 |
| 导航与生命周期 | Navigation Compose、Lifecycle ViewModel / Compose 集成 | 根页面导航与页面状态分离；路由重建不得重建网络状态所有者 |
| 并发与状态流 | Kotlin Coroutines、Flow / StateFlow | 用于网络任务、共享快照、连接生命周期和 ViewModel 状态 |
| HTTP 与 WebSocket | OkHttp | 同一网络栈负责 HTTP API 与 WebSocket；共享配置、超时、取消和错误分类 |
| JSON / DTO | kotlinx.serialization | 对服务端 DTO 做明确映射和校验；snake_case、camelCase、null 与缺失字段按接口合同分别处理 |
| 图片与封面 | Coil 的 Compose 集成 | 加载、缓存和显示封面；资源身份和当前歌曲身份由共享状态决定 |
| 本地偏好 | Preferences DataStore | 仅保存服务器地址、主题、状态环 UI 参数等非业务偏好 |
| Android 系统媒体集成 | Android 平台 MediaSession、AndroidX Core NotificationCompat/MediaStyle，以及满足后台生命周期所需的服务组件 | 将远端播放状态映射至系统媒体控件；不启动本地音频播放器或解码 NAS 音频 |
| 单元与协议测试 | JUnit、kotlinx-coroutines-test、OkHttp MockWebServer（或经阶段合同确认的等价测试工具） | 覆盖 DTO、共享状态、幂等操作、HTTP 错误和实时协议 |
| UI 测试 | Compose UI Test、AndroidX Test | 验证导航、可访问性、主题、关键状态和主要交互 |
| 持续集成 | GitHub Actions + Gradle Wrapper | 执行构建、测试、Lint，并保存可供验证的 APK artifact |

### 4.2 版本与工程约束

- 工程骨架阶段选择当时兼容且稳定的 Gradle、AGP、Kotlin、Compose BOM、AndroidX 与 JDK 版本，并通过统一版本目录管理依赖；本总规格不提前锁死可能过期的具体版本号。
- 工程必须提交 Gradle Wrapper、依赖版本目录、必要的 Kotlin/Compose 编译配置和测试配置；不能依赖开发者机器上未声明的全局 Gradle。
- CI 至少执行 Debug 构建、单元/协议测试与 Android Lint；构建成功后保存 Debug APK。Release 签名由后续发布合同处理，密钥不得提交到仓库。
- 包名/applicationId、应用图标、启动图、发布签名配置和精确版本号在工程骨架阶段冻结，不阻塞本总规格的产品边界。
- 版本升级应验证最低 API 26 兼容性，不能为追逐新版依赖而悄悄提高最低系统要求。

### 4.3 明确不采用的技术

- 不使用 WebView 或将 Vue 页面嵌入原生壳。
- 不引入 Room/SQLite 本地业务数据库，不将歌曲库、Queue、History、Playlist、Favorites 或完整播放快照存为第二份可独立修改的权威数据。
- 不使用 ExoPlayer/Media3 或其他本地音频播放引擎播放 NAS 音频；MPD-Server/MPD 负责实际音频播放与输出。
- 不为 Android UI 偏好增加服务端 endpoint；不在客户端复制 AutoPlay、Queue 编排、History 写入、MPD 绑定、播放恢复或曲库扫描算法。
- 不额外实现耳机按键专用功能或耳机集成验收范围。系统媒体会话可能受 Android 系统媒体路由影响，但耳机按键不是产品验收目标。

## 5. 应用信息架构与共享应用壳

### 5.1 四个一级入口

一级入口固定为以下四项，顺序固定：

1. **主页**
2. **搜索**
3. **音乐库**
4. **设置**

使用原生底部导航，图标、标签、选中态和触摸区域保持统一。四个入口只负责页面导航，不承载一套独立的播放状态。页面切换不新建 WebSocket，不重置共享播放快照，也不清除尚未解决的操作。

### 5.2 共享应用壳

根应用壳由以下层级组成：

1. 系统状态栏 / 安全区适配。
2. 紧凑 AppBar 与全局状态入口。
3. 当前一级页面的正文区域。
4. 迷你播放器（主页、搜索、音乐库显示；设置页不显示）。
5. 底部四项导航。

迷你播放器位于底部导航的正上方，正常参与布局，不覆盖列表。设置页不显示迷你播放器，但仍保留根导航和应用内全局状态入口。全屏正在播放页面是独立的沉浸式目的地，进入后隐藏根页面的迷你播放器与底部导航，返回时恢复进入前的根页面和滚动位置。

除全屏正在播放页外，所有页面都不展示完整音乐控制台，也不展示独立的播放进度条、上一首/下一首控制面板或扩展播放器卡片。搜索、主页和音乐库的歌曲行仍可提供被现有 API 支持的歌曲操作菜单，但这不构成第二个音乐控制台。

### 5.3 状态环与活动详情

- 保留现有客户端合同要求的**应用内全局状态环**。它是共享连接、活动、错误和 freshness 状态的视觉投影，不是新的状态源。
- 状态环可出现在应用自身页面范围内；不实现跨应用悬浮窗，不申请“显示在其他应用上层”权限。
- 点击后打开统一活动/状态详情。详情可显示同步中、断线、结果未知、失败、资源读取错误和成功信息；重试/重新读取严格遵守现有操作协调合同。
- 状态环的精确位置、尺寸、线宽、颜色优先级和动效曲线留到全局状态环阶段冻结。不能把状态环的颜色提示当作操作安全保证。

## 6. 迷你播放器

### 6.1 展示与布局

迷你播放器只包含：
- 专辑封面 / 默认占位图；
- 当前歌曲标题；
- 当前艺术家；
- 播放/暂停单一主按钮。

点击迷你播放器主体进入全屏正在播放页面；点击播放/暂停按钮仅发起相应控制，不应因按钮点击而进入全屏页面。迷你播放器不得显示 seekbar、上一首/下一首、歌词、输出信息卡片或完整播放控制区。

### 6.2 状态规则

- 内容来自共享快照与当前播放观察，不得由各页面单独查询或维护另一份 current song。
- 当当前歌曲身份与封面已确认时显示对应封面。无封面时显示应用内置占位图；不能因为读取失败而换成其他歌曲封面。
- 连接断开、观察 stale/unknown、同步中或当前条件不允许操作时，保留可解释的最后已知信息（如存在），播放按钮灰化且不能执行未经授权的操作；不得把 last-known 状态标成当前已确认状态。
- 没有当前歌曲时显示占位内容，播放/暂停不可操作。状态变化、单/双行歌曲标题、封面加载结果不得引起底部导航、AppBar 或页面正文几何抖动。
- 具体行高、封面尺寸、文字行数、长标题省略方式和切换动画在迷你播放器阶段冻结；符合原生触摸目标和无障碍语义。

## 7. 页面树与主要职责

以下定义主要信息架构，不预先冻结每个模块的内部间距、卡片样式、排序控件和细粒度动效。

### 7.1 主页：音乐发现

主页以发现内容为核心，不是播放控制台。首期信息架构预留以下模块位置：
- 猜你喜欢；
- 最近添加；
- 最近播放；
- 用户创建的播放列表。

各模块的精确顺序、每次显示数量、横向/纵向呈现方式、空状态、刷新行为和用户配置能力将在主页实施阶段前冻结。所有模块都必须依赖服务端已经提供的资源和事实。

**推荐内容能力边界：** 当前接口合同没有定义一个独立的个性化推荐引擎/API。Android 不得自行编造“猜你喜欢”结果、使用本地算法创建新的业务权威，或将静态假数据作为已实现功能。主页阶段必须先确认已有服务端数据能否准确支持相应模块；如不能，应将该模块留作明确的待实现区域，或另行提出经批准的后端需求。不得为了首页展示擅自增加后端复杂度。

“最近添加”可评估现有曲库排序能力；“最近播放”应使用现有历史资源；播放列表必须来自服务端歌单资源。具体字段、过滤规则和接口以对应 API 合同及阶段核对结果为准。主页不持久化一套独立的播放历史或自定义业务列表。

### 7.2 搜索

- 提供清晰的搜索输入区域与结果正文，使用现有服务端搜索/分类结果能力。
- 结果可展示歌曲及服务端返回的归类入口；点选归类后进入音乐库的对应详情。
- 结果必须区分输入为空、读取中、无结果、请求失败和结果 stale/unknown；不得用本地模拟结果掩盖 API 错误。
- 搜索输入、滚动位置与导航返回状态由本地 UI 状态管理；完整搜索业务、索引和结果解释属于服务端。
- 保留迷你播放器和底部导航。软键盘显示/隐藏不得遮挡输入、操作按钮或迷你播放器；具体键盘出现时的布局压缩/隐藏细节在搜索阶段冻结。

### 7.3 音乐库

音乐库是曲库与个人音乐集合的统一入口，至少涵盖：
- 全部歌曲；
- 专辑；
- 艺术家；
- 风格/流派；
- 年代；
- 标签；
- 播放列表；
- 收藏。

子分类可以使用紧凑的分段切换、列表入口或导航层级；不在总规格中强制复制 Web 标签样式。进入专辑、艺术家、风格、年代、标签或歌单详情后，应显示对应成员和可用操作。歌曲/集合的播放、Play Now、Play Next、加入 Queue 等动作只调用现有 API，由服务器决定集合解析和队列规则。

显示歌曲可用性、歌词、封面、源音频格式等元数据时，以服务端实际返回值为准；缺失、MISSING、UNREADABLE 与读取错误应能够区分。音乐库保留迷你播放器与底部导航，页面列表正常纵向滚动。

### 7.4 设置

设置页不显示迷你播放器；保留根导航、AppBar 和全局状态入口。主要分组如下：

**应用设置（本地偏好）：**
- 主题：跟随系统、浅色、深色；
- 服务器地址与端口；
- 状态环尺寸、位置偏移和线宽；
- 应用版本与基础信息。

**服务端系统设置（只复用现有接口）：**
- MPD 连接目标信息；
- 输出模式/启用状态及可用的既有输出操作；
- 服务端版本、统计、同步/连接诊断等 API 已提供的信息。

必须明确区分“Android 要连接的 MPD-Server 地址”与“MPD-Server 自己保存的 MPD 连接目标”。前者仅是 Android 本地偏好；后者是服务端配置。现有服务端合同注明，保存 MPD 连接目标并不代表活动连接立即切换，需按照当前部署要求重启服务后生效。界面不得把保存请求误报为连接已切换。

只显示服务端当前真正支持的功能。API schema 中存在某个模式不代表当前部署一定可用；对未支持的输出操作不得提供可点击的假功能。设置页的本地参数不得写入 MPD-Server，也不得因此创建新的后端 endpoint。

### 7.5 全屏正在播放页面

该页面是唯一完整音乐控制台。它提供两个主要内容状态：
- **正在播放**；
- **Queue / 队列**。

两者属于同一个全屏播放目的地，可使用清晰的分段切换入口；进入队列时不额外创建第五个一级导航入口。

正在播放区域的主要结构：
1. 主题适配的全屏背景；
2. 清晰的前景专辑封面，点击封面在封面与歌词显示模式之间切换；
3. 歌曲标题、艺术家、专辑等元数据；
4. 源文件音频信息与服务端输出观察的独立展示；
5. 进度与 seek 交互；
6. 上一首、播放/暂停、下一首等可用控制；
7. 当前歌词的原生 Compose 呈现。

当前 Web 行为合同规定的歌词解析、时钟、自动跟随、手动滚动恢复、触歌词 seek 保护和 current target 语义继续有效，不在本文重复定义。没有有效时间戳的普通文本不能伪造成逐句同步歌词；源文件 codec/采样率和 DAC/输出观察不能混为同一事实。

**Queue 区域**显示服务端权威队列，保留重复歌曲的 occurrence 身份、当前项、待播项及既有 Played 语义。点选播放、移动、删除、拖动排序、清空待播和保存为歌单必须调用现有服务端操作；Android 不在本地自行重排并提交“新权威队列”。详细队列操作按既有 Web 行为继承合同执行。

此页不新增未经合同授权的播放编排按钮或本地播放引擎。完整控件的具体几何、封面/歌词比例、按钮尺寸和动画，将在播放器阶段单独冻结。

## 8. 主题、颜色与视觉语言

### 8.1 主题切换

主题提供三个设置值：
- **跟随系统**（默认）；
- 浅色；
- 深色。

选择保存在 Preferences DataStore；跟随系统时响应 Android 当前主题。不得依赖 Android 动态取色替换应用的品牌强调色。所有页面、弹窗、迷你播放器、状态详情和系统栏使用同一语义颜色体系。

### 8.2 浅色模式

- 使用柔和、不刺眼的近白色背景，不使用高亮纯白铺满所有表面。
- 品牌强调色为 **#DE7622**。
- 通过细边框、背景色阶、轻量阴影和留白划分层次；避免将每个区域做成厚重独立卡片。
- 正文使用足够深的中性色，次要信息通过字重/明度层级表达；不能仅依赖浅灰色传达关键状态。

### 8.3 深色模式

- 使用行业常见的深色中性色表面；不继承 Web 蓝黑色品牌强调语言。
- 品牌强调色使用 **#BE7E4A** 或经对比度验证的暗化橙色变体。
- 正文、次要信息、边框、弹窗和底层区域采用清晰的明度分层，避免大面积纯黑造成刺眼或表面之间完全无法辨认。
- 深色主题中的橙色文本、填充按钮和图标可以使用不同语义 token：不能假设同一个橙色同时适合小字号文字、按钮背景和图标。必要时选择合适的前景色或更深/更浅的配套变体，但保留橙色品牌方向。

### 8.4 对比度、控件灰化与状态语义

- 常规正文与背景目标对比度至少 4.5:1；大文字至少 3:1；必要图标、边界和焦点标识至少 3:1。阶段验收需对浅色、深色以及专辑图背景上的前景内容实测。
- 状态同步中、断线、快照 stale/unknown 或当前条件不允许操作时，所有相关播放控件（包括上一首、下一首、播放/暂停、seek 等）必须同时满足**真实禁用**与**灰化表现**。不只是降低透明度后继续响应点击。
- 禁用控件使用中性灰色语义 token，不使用橙色强调色，也不能与正在同步的活动图形混淆。页面主体不应随控件禁用整体变灰；已确认的歌曲信息仍可展示，但 stale 信息必须明确标识。
- 控件状态不能只靠颜色表达：需要适当的可访问性语义、状态说明和真正的操作限制。对比度不足时优先调整前景/背景配色，不得为保持示例色值而牺牲可读性。
- 采用 Android 原生可访问性约定：可触控目标以至少 48dp 为设计基线，字体使用 sp 并尊重系统缩放。图标需要可访问名称；加载动画需提供可理解的状态语义。

## 9. 全屏专辑图背景

全屏正在播放页继续采用当前已确认专辑图片的**高斯模糊背景 + 主题适配蒙版**，而不是把该背景推广到所有页面。

- 前景专辑封面保持清晰；背景图片仅作为不参与布局、不接收触摸的视觉层。
- 无专辑图片时，使用应用内置默认占位图作为背景，再叠加相应主题蒙版。
- 背景身份只能来自现有播放观察和当前歌曲/封面资源身份；不得从 Queue 中随意选取歌曲、最后一次业务 current 或其他迟到的图片响应推断当前背景。
- 浅色模式使用能保留柔和明亮观感且保证文本可读的蒙版；深色模式使用能压低高亮区域的深色蒙版。实际模糊半径、蒙版透明度、切歌淡入参数和前景区域对比度在播放器 UI 阶段冻结。
- 图片加载/解码期间先显示稳定占位背景；资源身份已变化时丢弃迟到结果。缺图与读取错误分别表达，读取错误进入统一活动详情。
- 最低 API 26 必须有可用的模糊实现。若某种平台图形效果只在较新 API 提供，低版本需采用安全的兼容实现或静态降级；不得为模糊背景引入已弃用且不稳定的依赖链。
- 该全屏背景不改变内容布局、不覆盖安全区域中的交互、不因队列或设置页面切换而更新。

## 10. 服务器连接与网络边界

### 10.1 默认端口与部署约定

Android 与 Web 共用同一 MPD-Server 服务，不新建 Android 专用后端端口。

- **Android 默认服务器端口：18000。**
- **标准部署约定：NAS 主机对外端口 18000 → 容器内部 FastAPI 端口 8000。**
- 现有服务端部署文件 deploy/docker-compose.yml 目前默认将主机端口 8000 映射到容器 8000；若要采用本项目约定，部署时需将 MPD_SERVER_PORT 配置为 18000 或设置等效端口映射。本文不声称已修改上游 MPD-Server 的部署文件。
- 默认连接目标示例为 http://<NAS-IP>:18000；IP/域名不写死在 APK 中，首次使用时由用户填写。
- Android 不监听服务端口，不直接连接 MPD 的 TCP 端口 6600，也不要求额外开放 Android 专用端口。

### 10.2 API 与 WebSocket

- HTTP API 与 WebSocket 都从同一个配置的服务器 origin 派生；路径和 wire contract 以接口合同为准。
- HTTP 连接使用 http/https；实时连接分别使用 ws/wss。若经 HTTPS 反向代理接入，需使用 WSS，不能混用明文 WebSocket。
- 当前 NAS 局域网部署通常使用 HTTP。工程必须在 Android 网络安全配置中有意识地处理自托管 LAN HTTP 的 cleartext 限制，并将应用的业务网络请求严格限制到用户配置的单一服务器 origin；不能因允许 LAN HTTP 而接受任意 URL 或把服务端直接暴露到公网作为默认建议。
- 当前接口合同未定义 Android 登录/身份验证流程；不得虚构登录 API。自托管服务的安全边界遵循 MPD-Server 当前部署说明，不承诺无认证 HTTP 适用于公网。
- 保存新的服务器地址后，丢弃旧连接世代，重新建立 WebSocket 并获取新的完整权威快照。旧端点上尚未解决的 mutation 不得自动带到新端点或以新 key 重发；必须清晰展示其结果需重新确认。

## 11. 后台与锁屏媒体控制

### 11.1 系统媒体会话

用户需要在应用退到后台或锁屏时使用 Android 系统默认媒体控件控制 NAS 端播放/暂停、上一首和下一首；不要求耳机按键作为单独功能目标。

- 使用 Android 平台 MediaSession 与 MediaStyle 媒体通知，必要时配合正确类型的 Android 服务，以便应用退到后台后继续接收系统媒体控件命令。
- 系统媒体会话是远端播放状态的适配层，不是本地 Player；命令仍通过现有 API 与共享操作协调器发送到 MPD-Server。
- 系统元数据至少提供当前专辑封面、标题、艺术家，以及上一首、播放/暂停、下一首动作。系统媒体元数据必须与 App 内共享状态来自同一份状态 store。
- 不为通知另建第二条 WebSocket、独立的 current song 或 mutation retry 系统。服务组件与 UI 共享同一应用运行时；进程被重建后重新读取完整快照，不能依赖持久化快照当作当前事实。
- 服务/会话生命周期和新 Android 版本所需的服务类型、权限、通知能力，应在工程骨架/媒体会话阶段针对当时的 targetSdk 实测冻结；不允许因此引入本地音频解码。

### 11.2 通知生命周期与状态

- 首次显示媒体通知的条件是存在当前歌曲，且服务端实际播放状态已确认是 PLAYING 或 PAUSED。
- 用户明确确认 Stop，或完整权威状态确认不存在当前歌曲时，撤下媒体通知/系统媒体会话展示。
- 如果已有通知期间发生断线或观察 stale/unknown，可保留最后已知的曲目元数据并明确进入不可操作状态；App 发出的播放命令仍须通过实时状态检查和操作协调器。不能把最后已知播放状态改写成刚刚确认的状态。
- 系统媒体会话只发布当前真正可用的动作。Android/厂商系统负责绘制锁屏与系统媒体控件，因此不能保证所有设备把不可用动作画成完全相同的灰色；必须保证动作能力准确、不可用时不执行命令。App 内控件的灰化规则则由第 8.4 节严格保证。
- 若用户拒绝或系统限制必要的后台能力，应如实降级并在 App 内说明，不可伪称锁屏控制仍完全可用。

## 12. 共享状态、错误恢复与本地持久化边界

页面与后台媒体会话共同使用一个应用级运行时，整体职责如下：

~~~text
Compose Screens / ViewModels
          |
          v
Single App Runtime
  ├── Shared Snapshot Store
  ├── One Realtime Controller (WebSocket)
  ├── One Mutation / Operation Coordinator
  ├── Thin API Repositories
  └── MediaSession / Notification Adapter
          |
          v
OkHttp HTTP + WebSocket
          |
          v
MPD-Server (唯一业务与状态权威)
          |
          v
MPD (实际音频播放与输出)
~~~

- 完整快照、epoch、sequence、资源 revisions、current target、fresh/stale/unknown 与幂等恢复行为按照现有三份权威合同实现；本文不另造一套状态协议。
- Composable 与 ViewModel 只能拥有局部展示状态，例如搜索输入、当前路由、滚动位置、封面/歌词切换、弹窗、拖动草稿和动画；不能拥有独立的 canonical playback state。
- Repository 仅负责请求、DTO 映射和协议错误，不复制后端 Collection、Queue、AutoPlay、History、Playlist、Favorites 或 MPD recovery 算法。
- DataStore 仅保存本地偏好：服务器 origin/host/port、主题选择、状态环直径/偏移/线宽等。不得存储一份可继续编辑的业务曲库、队列、歌单、收藏或历史。
- 可以在内存中保留 last-known 信息供离线说明，但必须标记 stale/unknown；应用进程重新启动或连接更换后，需重新取得权威快照后才能开放依赖 fresh 状态的控制。
- 同一 mutation 的重试保留原 intent、key 和 payload；结果未知不等于失败。页面切换或服务组件生命周期不得丢失未解决操作的 owner，也不得创建第二次意图。

## 13. 质量基线与实施前检查

### 13.1 自动验证

- DTO/协议单测：字段缺失/null、enum 新旧值、错误 body、204、未知结果和 snake_case/camelCase 映射。
- 共享状态测试：初始快照、断线重连、旧 epoch/sequence、并发 invalidate/GET、旧连接迟到响应、stale/unknown 与 current target 变化。
- mutation 测试：Idempotency-Key、重复点击、超时结果未知、同 key 原 payload 恢复、读回失败，以及 endpoint 变更时禁止重放。
- UI 测试：四个一级入口、设置页不显示迷你播放器、主页/搜索/音乐库显示同一迷你播放器、全屏播放器返回行为、主题切换与关键禁用状态。
- MediaSession 测试：播放中/暂停元数据、系统动作触发既有操作、断线时动作不可用、明确 Stop/无 current 时撤下通知、进程重建后重新取得服务端状态。
- 在 392dp 参考宽度和较窄手机竖屏上验证：正文不会被迷你播放器/底部导航覆盖；软键盘与系统栏 inset 正确；大字号不裁切关键控件。
- 浅色、深色、专辑图很亮/很暗、无封面、封面读取失败、加载中、断线与长文本均纳入 UI/人工验收。
- CI 成功需由实际 Gradle 命令输出证明；文档或代码审查不能替代构建与测试证据。系统媒体控件的最终外观还需在真实 Android 设备上验证，模拟器截图不能证明所有厂商锁屏样式相同。

### 13.2 每阶段冻结

总规格冻结稳定的产品边界；以下内容在相应阶段开始前建立单独的细化合同：
- 工程骨架：applicationId、具体 SDK/依赖/Gradle/JDK 版本、网络安全配置、目录与模块边界、CI 命令。
- 应用壳/主题：语义颜色 tokens、AppBar/底部导航/迷你播放器准确尺寸、窗口 inset、状态环尺寸/位置/线宽、主题对比度测量。
- 主页：模块数据源、顺序、数量、无数据行为、刷新机制以及“猜你喜欢”的真实能力边界。
- 搜索/音乐库：查询交互、归类与详情导航、长列表和操作菜单。
- 全屏播放器/Queue：精确排版、封面与歌词切换、拖动/seek 交互、队列手势及动效。
- 媒体会话：服务生命周期、系统权限、通知/锁屏行为、系统动作与 stale/断线测试。
- 发布：签名、版本号、APK 命名与发布流程。

任何细化合同不得以实现方便为理由增加本地业务数据库、另建后端业务逻辑、把 Web 的蓝色强调主题带入 Android，或把完整播放器控制台散落到其他页面。

### 13.3 上游基线更新

在一个新功能阶段开始前，检查目标 qyxx2/MPD-Server/main 是否已推进。如果推进：
1. 读取新的实际 HEAD；
2. 比较相关 server/app/api 与 schemas、通用错误/幂等中间件、Web services/stores/runtime、现行领域规格和测试；
3. 确认端点、DTO、状态与行为合同是否变化；
4. 先更新本仓库受影响的合同和引用，再制定实现阶段计划；
5. 不因旧快照仍存在于文档而复用被删除或已经改变的 API。

## 14. 非目标

- 不做平板、横屏双栏或桌面布局。
- 不做跨应用悬浮窗。
- 不在 Android 本地播放或解码音乐，也不直接连接 MPD TCP 控制端口。
- 不在客户端维护业务 SQLite/Room 数据库，不实现离线业务编辑。
- 不新增推荐、播放编排、持久化历史或后端配置 API，除非先报告现有能力缺口与影响并获得单独批准。
- 不为耳机按键建立独立功能和验收范围。
- 不把所有 Web 组件/页面或 Web 蓝色视觉系统原样移植进 Android。
