## 1. 目标与范围

Task 4 负责全屏正在播放/歌词/Queue/Played 的呈现与交互，以及现有 Web/API 语义在原生 Android 中的等价实现。视觉采用用户选择的 B 方向：大封面优先、控件精简、减少边框和卡片，不为层级而增加明显的矩形容器。参考用户提供的 Queue 截图，只借鉴队列行的比例、拖拽柄、当前项整行高亮和溢出菜单布局；不得复制其中品牌资产或示例音乐数据。

本规格决定 Task 4 的 UI 呈现和本地交互状态；不创建第二套播放状态、不改变服务端 Queue 语义、不另建 API/播放引擎、不使用 WebView。服务端快照/回执/资源与现有 Web 行为合同仍是业务权威。

## 2. 已确认的设计决定

### 2.1 全屏页面与安全区

- 页面适配长纵向手机屏幕，优先利用垂直空间，不在顶部/底部留下大块无意义空白。
- 延续 Task 3 edge-to-edge 约束：系统状态栏保持可见；所有可交互顶部内容避开 status bar、DisplayCutout 和系统手势安全区域。不得把系统栏高度硬编码为固定 dp。
- 全屏正在播放页不显示顶部返回、收回或“正在播放/队列”切换控件；状态栏下方至专辑封面之间保持干净，不放额外标题栏或装饰性控件。Queue 页同样不显示“队列”标题；从安全内容顶部直接放置控制信息行，左侧显示“剩余播放时间：--:--”占位，右侧显示带简洁线条图标的“清空待播”和“保存歌单”。后端未提供剩余播放时间时只能显示占位，不得推算/伪造数值。
- 全屏正在播放页与 Queue 页均不显示收回按钮。播放器从 WindowInsets 确定的安全内容顶部手势带或专辑封面图像区域响应纵向下滑关闭；Queue 仍只从安全内容顶部手势带关闭。两者均不得要求从真实系统状态栏内部起手，以免与 Android 通知栏下拉冲突；不得硬编码状态栏高度。
- **正在播放页与 Queue 页的背景画布必须覆盖完整窗口**：从窗口物理顶部延伸到窗口底部，包含透明状态栏/导航栏背后的画布；不得把背景画布放在已经应用 safe Insets padding 的父容器内。两页的前景可交互内容才应用实际 safe-content padding，顶部退出手势带从系统状态栏/挖孔安全区之后开始。系统状态栏图标与其手势仍归 Android 系统管理；应用只延伸内容画布，不伪造系统栏。Queue 使用已共享的 PlayerArtworkBackdrop；其全屏背景与正在播放页一致，不能因路由容器而在状态栏/导航栏周围出现不同颜色的矩形区域。
- 在正在播放页，纵向拖动识别与封面点击切换必须通过 touch slop/方向判定区分：满足向下拖动阈值才退出，普通点击不得触发关闭；未来 Batch 4 的封面点击转歌词行为必须保留其 tap 事件，不在本次修正中提前实现歌词。Queue 页仅从 WindowInsets 确定的安全内容顶部专属手势带下滑退出；正文列表使用原生滚动进入历史，不能与退出手势同时触发。
- 下滑退出必须与 Queue 列表滚动、Played 历史展开、歌词手动滚动、seek 拖动、Queue 行拖拽区分：播放器手势区仅覆盖安全内容顶部带与专辑封面图像本身，不覆盖曲目信息文本/未来歌词区域、进度条/控制/底部入口；Queue 仍只有顶部专属手势带触发退出，正文使用原生滚动浏览 Played 历史；行拖拽柄与进度触摸拥有更高优先级且不得被页面手势抢夺。
- 歌词模式有专属“返回封面”图标/按钮；其含义仅为退出歌词模式回到封面模式，不关闭全屏播放器。
- **播放器交互式下滑与迷你播放器展开动效：** 从安全内容顶部带或专辑封面图像区域开始时，完整全屏播放器（包括进度/控制/底部入口）须以 1:1 连续垂直位移跟随手指。纵向手势未达到关闭阈值或收到 `ACTION_CANCEL` 时，页面平滑恢复原位；超过阈值后，继续向下离屏再返回根页面。手势期间播放器两个上边角随位移迅速增大圆角，最大 32dp；底层页面由轻度模糊逐渐变清晰，播放器完全离屏后底层恢复正常清晰度。底层仅为当前根页面的视觉呈现，仍使用既有 AppRuntime/服务端快照，不创建第二份播放状态。
- 从迷你播放器进入全屏时，不使用整页渐隐；以约 250ms、从迷你播放器所在下方位置向全屏扩展的垂直缩放/展开为主动效，并与底层由清晰到轻度模糊同步完成。动效应直接、协调，不延长到让人等待；Queue 页面不引入迷你播放器展开动画或改变其原有顶部关闭语义。

### 2.2 正在播放 · 封面模式

- 以大专辑封面为视觉主体。封面尺寸由可用宽度和扣除安全区、文字、进度、控制、底部锚点后的剩余高度共同约束；不能按某个截图像素固定，不能因长标题/大字体造成底部控件溢出。
- 封面下方按行显示：曲名、艺术家、专辑。曲名字号最大且额外加粗；艺术家次之；专辑最小。曲名按可用宽度合理换行或省略，不能挤压/覆盖控制区。
- 艺术家与专辑是可点击导航入口，行为继承 Web：分别进入对应艺术家/专辑列表。仅有视觉文字不等于必须扩大点击到整屏；实现需保证可访问的触控热区且不让两个目标互相重叠。
- 进度条、已播/总时长和播放控制保持明确可用。上一首、播放/暂停、下一首为主播放控制，不再增加重复的装饰性按钮。
- 源文件格式信息（例如 FLAC · 24 bit / 96 kHz）小字号、居中、紧贴进度条（含已播/总时长）下方，并位于主播放控制上方；间距紧凑，不放在独立边框/卡片中。此数据来自当前歌曲源文件元数据，不得伪装成实际 DAC 输出格式。
- DAC/输出观察状态图标放在全屏底部左侧，线条风格、笔画、视觉重量与中/右两个底部图标一致。状态语义必须继承 Web/服务端观察；不得把 output ACTIVE 描述成硬件已发声或 bit-perfect。
- 底部有三个无底框图标：左侧 DAC/输出状态；中间独立的“正在播放”页面指示；右侧 Queue 入口。仅当前页面图标使用品牌强调色（浅色主题沿用 #DE7622 的语义色；深色主题使用 Task 3 已定义的可读橙色变体），其余中性色。图标周围保留足够触控热区，不画胶囊、方框或填充按钮背景。
- 中间“正在播放”指示必须与播放/暂停控件使用不同图形语言。优先使用独立的波形/均衡器式标记，不使用三角播放符号或双竖暂停符号；具体矢量图标仍需在最终图标检查中确认。
- 不新增独立的卡片边框来分隔歌曲信息、音频参数、DAC 状态或底部入口。通过字重、间距、对齐和少量颜色区分层级。

### 2.3 歌词模式

- 点击封面区域切换到原生歌词模式；不使用 WebView。
- 歌词模式隐藏曲名、艺术家和专辑元信息，并使用原封面与元信息占据的主内容区域呈现歌词。歌词区域可比封面本身更高，但不能侵入或推动进度条、播放控制、源文件参数和底部三个图标。
- 模式切换只替换“封面 + 曲目信息”这一主内容区域：播放进度、时长、播放控制、源文件参数及底部三个图标的锚点/布局保持稳定，不因模式切换而整体跳动。
- 歌词视口使用返回封面按钮所在顶部区域下方至进度条前安全间距之间的可用高度，底部保留与进度条的安全距离；视口扩展不得移动进度、播放控制、源文件参数或底部三个图标的锚点。
- 歌词字体尽可能大：当前行使用 34sp / 40sp 行高并以品牌强调色突出，其余行使用 28sp / 34sp 行高和可读的中性色；字号继续遵循系统字体缩放。每条时间轴歌词最多占两行，短歌词按实际需要占一行，不留空白占位行；若文本超过两行，第一行保持可读，第二行水平滚动显示剩余文本。不得插入占位、重复或额外歌词行来填满视口，只呈现服务端返回的真实歌词 cue；不使用卡片/逐行边框。
- **解析行为与 Web 实现保持一致。** Android 只解析服务器 SongResponse 中的 `lyrics` / `lyrics_format`，同时保留 `lyrics_source` / `lyrics_status`；内嵌歌词的读取和 sidecar 优先级由服务器决定；当前固定扫描器从 FLAC 的 lyrics/LYRICS/unsyncedlyrics comment 或 MP3 的 ID3 USLT 帧提取内嵌歌词。Android 不直接读取媒体 tags 或重新扫描文件；只要服务器返回的 embedded 文本含合法时间戳，客户端就按同一 parser 识别。只解析 `lrc` / `text` 两种 format（不区分大小写）；旧资源即使标记为 `text`，内容含有效时间戳时仍识别同步 cue。识别 `[mm:ss]`、`[mm:ss.f]`、`[mm:ss:fff]`，支持一行多 timestamp、`[offset:+/-整数毫秒]`、稳定排序、相同时间戳和 Web 原有 metadata note 过滤。分秒边界与小数转换保持 `web/src/components/player/lyrics.ts` 的现行算法：分钟不限位、秒 00–59；小数位按 `Number("0." + digits)` 解释，因此 `.5` = 0.5s、`.05` = 0.05s、`.005` = 0.005s，不自行套用另一种 LRC 小数换算。active cue 取 playback position 加 offset 后不晚于该时间的最新 cue；seek 目标需减去 offset。
- **时间轴歌词的交互合同：** 初始自动跟随当前播放行。用户手动上下滚动时立即暂停自动跟随；以最后一次手势结束/实际滚动作为计时起点，连续 3 秒无新交互后，若没有正在进行的手势或文本选择，则定位到此时最新 playback clock 对应的 active cue 并恢复跟随。继续滚动重置 3 秒计时。点击具体、当前可 seek 的时间轴歌词行，向 B3 的共享 PlayerActions 提交一个 seek，目标为 `cue.seconds - offsetMs / 1000`；之后高亮/跟随仍以服务端观察与 readback 为准。拖动、长按、文本选择或 pointer cancel 不能误当作 cue tap，也不能发送 seek。
- **普通无时间轴文本的交互合同：** 保留原始文本并允许任意上下滚动；不伪造 active line、时间轴、逐句同步或点击 seek，并且停留 3 秒后不自动返回某一行/顶部，保持用户正在查看的位置。无有效 cue 的 metadata/note、同步歌词但播放时钟 unknown、missing 与 read_error 分别展示，不能混成单一空状态。歌词读取失败时即使服务器返回了可显示的 embedded fallback 文本，也必须保留 read_error 提示。
- `lyrics_source` 等来源字段仍由服务端权威提供并保留；不得把内部来源标记 `embedded` 直接显示成“来源：embedded”。必要的错误/同步状态提示仍正常显示。
- 歌词模式在主内容区域左上角提供回到封面的简洁水平左箭头；图标绘制尺寸为 18dp，采用圆角端点和适度加粗线条，避免过大或尖锐，外围触控热区保持 48dp，并在模糊封面背景上具备足够对比度。该图标只切回专辑封面，不提供退出全屏的独立按钮。歌词区域不再显示“同步歌词”这类额外标题，也不显示曲名/艺人/专辑，以免挤占歌词空间。

### 2.4 Queue / Played 页面

- Queue 页沿用 Web 的业务模型和操作菜单，不以视觉重排改变业务语义。进入 Queue 时定位当前实际确认的 Queue occurrence（position 0/current）；若实际播放未确认，必须按 Web 规则显示未确认状态，不得伪造 current。
- 严格继承 Web Queue 的历史位置/排序语义：Played（position < 0）是同一滚动列表中的真实行，按 position 从旧到新排列，紧接着是当前 occurrence（position 0）与 Web 定义的 next 候选。初次进入和离开后重进时，视口锚定当前 occurrence；Played 在它上方已存在，向下滑动时自然进入可见区域。只重置 UI 滚动位置，不修改 Queue 数据或播放状态。
- **Played 历史行的区分蒙版（B8 补充）：** 对 position 小于零的历史行内容叠加极薄白色蒙版（白色 alpha 为 0.045）；current 与 pending 行不叠加此蒙版。蒙版只承担视觉区分，不改变行高、点击/菜单行为或服务端 Queue/Played 数据。
- **历史使用原生队列滚动与惯性。** Played 行始终加入同一个 LazyColumn，不再有零高度历史区、独立 reveal 高度或拦截下拉/惯性的自定义手势。视口初始定位到当前 occurrence；向下拖动或快速轻扫时，沿用 LazyColumn 的标准滚动、速度与惯性，先显示最近播放项，再随着滚动深入显示更早项目。
- **滚动释放沿用原生惯性。** 不在 pointer-up/cancel 中清除或写入额外历史计数；普通 LazyColumn scroll/fling 自行决定滚动结束位置。再次进入 Queue 时恢复到 current 锚点，历史数据本身不会因滚动或页面离开而改变。
- **Task 4 历史数据策略：** Queue/Played 优先使用 fresh snapshot 的 position<0；snapshot 不 fresh 时沿用现有一次 GET /api/history/played fallback。历史 occurrence 直接纳入同一 LazyColumn，并由正常列表滚动/惯性呈现；客户端只限制 metadata prefetch 并发/窗口，不用 gesture reveal 或重复 GET 模拟分页。
- 当前服务端 API 的 GET /api/history/played 和 GET /api/playback/queue 都没有 limit、offset 或 cursor 参数，前者返回整个当前会话 Played 列表。因此 Task 4 不新增/假设服务端分页接口，不重复调用全量 endpoint 来模拟分批网络读取。History occurrence 始终属于同一 LazyColumn，由列表自身虚拟化绘制；进入 Queue 时预热最近一段历史的歌曲元数据，向更早历史滚动时按可见范围扩展有界预取，不因拖动指针或滚动位置逐帧发起 history 请求。真正的 server-side 分页属于独立的服务端/API 变更，不纳入本 Task 范围。
- 使用 Compose LazyColumn 与稳定 occurrence key（queue_item_id；Played 行 key 加历史语义前缀以避免与 current/pending 重复 ID 冲突）。所有真实历史行从初始数据集参与滚动顺序，列表视口锚定 current，而不是在手势时才创建/测量历史区。复用 Runtime 的 canonical fresh snapshot；snapshot 不 fresh 时沿用已有一次 GET /api/history/played fallback 与 generation guard。预热最近历史的元数据并在滚动时扩展邻近预取范围，既不改变历史数据权威，也不制造 API 分页或虚假 occurrence。
- 当 current 与 pending 的最小行高不足以填满视口时，仅在列表末尾添加透明布局 spacer 来提供足够的向前滚动范围，使 current 可稳定锚定顶部。它不是 occurrence、不会显示操作入口，也不会进入服务端 Queue；历史行始终存在于同一个 LazyColumn。
- 每行结构参考用户截图：左侧 2 列 × 3 行共 6 个点的拖拽柄；中间专辑缩略图；右侧曲名/艺术家与专辑/可用的小型元数据标识；最右侧三点溢出菜单。当前项保持现有主题主色与 0.10 透明度，仅小幅提高饱和度（最多 0.92），色相、亮度和透明度不变，视觉保持克制。其它项目背景完全透明，不使用不透明白色/表面色覆盖共享模糊背景；相邻项目之间使用约 0.75dp、低干扰的主题 outlineVariant 分隔线。不在每个项目周围加卡片框。
- **所有模态浮层使用统一的浅薰衣草色偏表面。** 包括行操作下拉菜单、清空待播确认、保存歌单、DAC/输出详情及连接/活动底部表单等当前和后续新增的 dialogs、popup menus、modal sheets。统一通过共享 `dialogSurfaceColor()` 从当前主题的 `surface` 向柔和薰衣草目标色混合 18%（浅色目标 `#F4EDFF`，深色目标 `#312C38`）取得颜色；保持与全局主题可读性一致，不各自硬编码不同的弹窗背景色。
- 拖拽柄采用 2×3 六点图形。为贴近用户参考图，可在所有行保留同一列的六点视觉锚点；交互严格继承 Web：仅 position > 0 的待播项是真正可拖拽的入口，current/Played 的六点必须呈禁用/非交互状态，不得启动排序。长按启动后，原行留在队列原位并降至约 0.30 不透明度；另创建与原行尺寸/内容对应的浮动拖动项，覆盖轻微半透明白色蒙版、主题强调色描边和柔和阴影，以手指的 X/Y 位移持续跟随。拖动项与插入提示均为临时 UI 草稿，不得乐观修改 canonical 行序；松开时最多提交一次按 `queue_item_id` 定位的 reorder intent，取消/基线失效不提交，最终顺序以服务端快照读回为准。
- 三点菜单复用 Web 现有的逐项操作与禁用条件；点击行播放指定 occurrence，必须以 `queue_item_id` 定位，不能用 song_id、URI 或标题替代。
- 三点菜单必须锚定被点击行的三点按钮附近，以紧凑下拉浮层呈现，不得全屏居中；点击弹窗/浮层以外的任意空白区域、按系统返回键均关闭菜单。最大宽度 264dp，只有单行居中曲名，不重复呈现艺术家/专辑信息；曲名约 18sp，操作文字约 16sp，所有选项水平居中并避免大块留白。不得使用盖住整屏的重型遮暗层。此条只规定视觉与关闭行为，菜单动作与禁用条件继续复用现有 Web/QueueMenuPresentation 规则。
- Queue 页面与正在播放页共享同一 `PlayerArtworkBackdrop`、当前确认媒体投影、`PlayerArtworkMemoryCache` 和 cache key；Queue route Surface 必须透明，底层只复用现有已预载的模糊封面并应用同一主题蒙版。不建立 Queue 专属图片读取/缓存 owner，不因显示背景改变播放确认、Queue 状态或服务端权威边界。顶部操作行左侧只显示剩余播放时间占位，右侧放带简洁线条图标的“清空待播”和“保存歌单”；不得显示重复页面标题。
- 清空只清除服务端定义的待播项，不等于 Stop；保存 Queue、Play Now、Play Next、Add to Queue、删除待播项、随机播放等都复用现有 Web/API 语义与共享 Mutation Coordinator，不在 Android 端重写业务算法。
- 队列底部沿用与正在播放页相同的三个无底框图标和当前选中染色；Queue 图标选中。顶部不放正在播放/队列切换按钮。离开 Queue 时清除当前页面的历史展开/滚动暂态；再次进入从当前 occurrence 重新定位。

## 3. 响应式与可访问性

- 所有尺寸以 dp/sp 与 WindowInsets/DisplayCutout 几何计算，不按参考截图像素硬编码。优先覆盖项目最小宽度 392dp，并测试更窄宽度、短屏/横屏、大字体、长标题与无封面状态。
- 触控目标至少 48×48dp；图标本身可以小于触控热区。底部图标之间不能重叠；DAC 状态长文本应转入详情/辅助说明，不挤压中心与 Queue 图标。
- 深浅主题遵守 Task 3 主题选择和颜色对比度合同。封面模糊背景需有足够蒙版对比度；品牌色只承担选中/当前歌词等强调，不用于所有装饰。
- 动效应稳定且轻量：封面/歌词切换不重排控制区；队列滚动/拖拽无逐项弹出或闪烁；切歌时封面、歌词、歌曲元数据必须基于同一当前 occurrence，不能串曲。
- 缺封面、无歌词、普通文本歌词、歌词读取失败、未知/过期播放观察和输出观察不 fresh 等状态须分别处理，不能以静态示意内容代替真实状态。

## 4. 非目标与禁止项

- 不实现第二套播放状态、第二个 WebSocket/HTTP owner、页面级 mutation owner、客户端队列副本或独立的播放引擎。
- 不以 `playback.state` 单独判断真实播放；不把 stale/unknown/UNBOUND/EXTERNAL_DRIFT/SYNC_FAILED 状态渲染成已确认播放。
- 不通过本地按 song_id 去重、重建 occurrence 或自行改变 Queue position 来“修复”服务端状态。
- 不新增 WebView、服务端 API、数据库或依赖库来解决纯 UI 问题。
- 不把视觉预览中的歌曲、专辑封面、时长或歌词作为应用默认数据。
- 不在未确认的设计决策上自行冻结最终色彩/图标/手势边缘行为。

## 5. 已关闭的产品选择

- **主题：** 播放器和 Queue 跟随应用当前主题；只对封面模糊背景叠加保证文字对比度的主题蒙版，不强制整页进入深色主题。
- **下滑退出：** 不拦截系统状态栏。播放器从 WindowInsets 确定的安全内容顶部带或封面/曲目信息区域向下拖动关闭；完整播放器层跟手移动、上边角圆角随位移增加、底层页面随拖动逐渐清晰；未达到关闭阈值或手势取消则恢复。迷你播放器进入全屏使用约 250ms 的垂直展开而非渐隐。Queue 仍只从顶部手势带关闭，正文由原生列表滚动进入 Played；播放器封面 tap 与纵向 drag 必须分开；歌词正文内部滚动不得误触发全屏退出。
- **六点柄：** 所有行保持六点柄列对齐。只有 `position > 0` 的待播行可长按排序；当前行和 Played 行的柄以低对比度呈现并禁用交互。
- **底部三个图标：** 左侧 DAC/输出状态、中间独立的正在播放波形/均衡器标记、右侧 Queue；无背景框/胶囊，当前页面图标染色。图形语义不得与主播放/暂停按钮冲突。
- **历史边界：** Played 只来源于当前服务端 Queue snapshot 中的 `position < 0` occurrence；不创建本地持久历史或无限扩展服务端未提供的数据。
- **顶部切换控件：** 移除全屏页面顶部的“正在播放/队列”切换；切换由底部三个无框图标完成。封面上方保持干净，歌词模式也不加额外标题栏。
- **歌词模式：** 隐藏曲名/艺术家/专辑，将封面及元信息主内容区域替换为填充可用主内容高度的歌词视口；每条 cue 最多两行，超长文本的第二行水平滚动显示余下内容。左上角提供简洁的水平左箭头返回封面操作，底部进度/播放控制/格式参数/三图标位置固定。时间轴歌词遵循 Web parser、offset-corrected cue seek、手动滚动后 3 秒回到最新播放行；普通无时间轴文本可自由滚动且永不按计时自动回位。具体边界见 `2.3。
- **历史数据策略：** 复用现有 API/新鲜快照，把已取得的 Played occurrences 直接纳入同一 LazyColumn 并由列表自身虚拟化绘制；预取采用有界元数据窗口。绝不新增服务端分页或重复读取全量历史来模拟网络分批。
- **历史滚动：** 不再使用独立的连续 reveal 窗口。current 与 Played 在同一个 LazyColumn 中，利用正常滚动和 fling 惯性进入历史；内容按 oldest → newest → current → pending 排列，position -1 紧邻 current。
