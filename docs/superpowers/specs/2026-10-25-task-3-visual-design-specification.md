# Task 3 Visual Design Specification / Task 3 视觉设计规格

> **状态：视觉方向与关键参数已依据用户提供的实机截图及对话冻结。**
>
> **适用分支：** `feature/task-3-native-app-shell`
>
> **设计参考：** 用户在 2026-10-25 提供的 Apple Music 实机截图。仅借鉴其简洁布局、比例、列表行、导航图标风格与迷你播放器结构；截图仅作设计参考，不作为应用资产，不复制 Apple Music 的产品信息架构或品牌颜色。

## 1. 目标与权威关系

本规格负责冻结 Task 3 原生应用壳、根导航、首页占位容器、音乐库入口列表、迷你播放器、全局状态环与通用视觉语言的视觉表现。目标是“简约但不简陋”：内容层级清楚、组件比例稳定、留白适度、控件真实可用/禁用，不以厚重卡片或装饰性动效制造复杂感。

本规格细化以下权威文件，不取代它们：
- [Android 客户端产品与工程总规格](2026-10-24-android-client-product-and-engineering-spec.md)：根入口顺序、页面范围、主题品牌色、迷你播放器及状态语义。
- [客户端权威边界与架构规格](2026-10-23-android-client-boundary-and-architecture.md)：唯一 Runtime、状态环和本地偏好边界。
- [Web 行为继承规格](2026-10-23-android-web-behavior-contract.md)：单曲/集合操作、排序、随机选择、状态与错误语义。
- [后端接口与实时协议规格](2026-10-23-android-backend-api-contract.md)：现有端点、参数及服务端权威行为。
- [Task 3 应用壳合同](2026-10-25-task-3-native-app-shell.md) 与 [Task 3 实施计划](../plans/2026-10-25-task-3-native-app-shell.md)：Task 3 的代码范围、Batch 和验证门。

优先级规则：服务端/API 与 Web 行为合同决定业务语义；产品总规格决定已冻结的产品边界；本规格决定本 Task 内的视觉参数。若发生冲突，不得以视觉复刻为理由改变已冻结的根导航、品牌强调色或业务操作语义。

## 2. 设计决策

### 2.1 采用的方向

采用“截图比例与简洁感 + 本项目已有品牌色 + Android 四入口导航”的方向：
- 保留截图中的柔和浅色背景、黑色主文字、次级灰色文字、细分隔线、轻量线性图标和紧凑布局。
- 参考截图的组件比例、文字层级、列表行间距与迷你播放器高度，不要求按截图像素盲目缩放。
- 保留现有橙色品牌色，不采用截图的红/粉色选中态。
- 使用本项目既定的四个根入口，不复制截图的五项导航。
- 主页仅提供明确的结构容器，不复制 Apple Music 的推荐、专题或曲目内容。

### 2.2 明确不采用

- 不使用 Apple Music 的红/粉色作为选中态或品牌色。
- 不复制 Apple Music 的五入口导航、“新发现/广播”页面、全局三点菜单或“最近添加”模块。
- 不把截图中的歌曲名、封面、推荐、收藏或历史作为应用里的示例业务数据。
- 不复制 Apple/Apple Music 商标、专辑封面或截图中的品牌资产。
- 不为追求视觉一致性引入 WebView、额外播放引擎、页面级状态 owner 或本地业务算法。

## 3. 布局与几何基线

以下为目标手机竖屏的 Compose 设计基线，数值均为 dp，字体数值为 sp。系统状态栏、导航手势区和显示挖孔由 Android Window Insets 处理，不将实机截图中的状态栏或厂商系统 UI 画进应用。

| 项目 | 冻结值/规则 |
|---|---|
| 设计宽度基线 | 以项目规格中的最小 392dp 手机宽度适配；宽度变化时采用弹性布局，不按截图像素硬编码 |
| 页面水平内边距 | 常规 20dp；窄屏可收至 16dp，不能引起横向溢出 |
| 间距尺度 | 以 4dp 为基数：4、8、12、16、20、24、32dp |
| 普通页面 AppBar | 内容高度 48–56dp，不包含系统状态栏 inset；紧凑，不能挤压正文 |
| 页面标题 | 普通页面 20sp；音乐库首页可用 28sp、粗体，形成截图中的主标题层级 |
| 正文滚动区域 | 占用 AppBar 与底部固定区域之间的剩余空间；不能被迷你播放器或导航栏覆盖 |
| 分隔线 | 1dp，使用中性分隔色；列表分隔线从标题/内容列起始处缩进，避免贯穿图标列 |
| 表面形状 | 以简单平面与细边框为主；需要容器区分时使用 8dp 左右圆角，避免每个模块都成为厚重卡片 |
| 阴影 | 默认无明显阴影；必要的层次通过表面明度与细边框表达 |
| 触控区域 | 所有交互控件目标至少 48×48dp，即使图形本身更小也必须保留触控热区 |
| 字体 | 使用 Android 原生无衬线字体；字号用 sp，并尊重系统字体缩放 |

## 4. 颜色与文字层级

### 4.1 品牌色与主题

- **浅色强调色：** `#DE7622`，保持产品总规格既有决定。
- **深色强调色：** `#BE7E4A`，或仅在对比度实测证明必要时调整为同方向、可读性更好的橙色变体。
- **浅色背景：** 柔和近白色，不使用高亮纯白铺满所有区域；建议基础背景 token 为 `#F7F7F5`，抬升表面可用 `#FFFFFF`。
- **深色背景：** 深色中性表面，避免大面积纯黑；建议背景 token `#171717`，抬升表面 `#202020`。
- **主文字：** 浅色使用接近 `#171717` 的深中性色；深色使用接近 `#F4F4F4` 的浅色。
- **次级文字：** 浅色建议 `#737373`；深色建议 `#B8B8B8`。
- **分隔线/描边：** 浅色建议 `#D8D8D8`；深色建议 `#3A3A3A`。
- **禁用态：** 使用中性灰色文字、图标与表面，不把橙色强调色用于表现不可操作状态。
- **强调色角色：** `#DE7622` 是浅色主题的品牌强调色；小字号强调文字/选中标签如未达到 4.5:1，使用同色系对比度变体（建议 `#A84F0B`）。深色主题采用 `#BE7E4A` 或经对比度验证的同色系变体；不要要求一个橙色色值同时适用于小文字、填充背景和所有图标。

以上中性色为视觉 token 的初始参考值；实现时须对文字、图标、边界、焦点与禁用态进行浅/深色对比度检查。正文目标至少 4.5:1，大文字至少 3:1，必要图标/边界/焦点标识至少 3:1。若某个 token 对比度不足，应调整对应语义色变体，不能把可读性让位于色值表面一致。

### 4.2 字号层级

| 用途 | 建议字号 | 字重/表现 |
|---|---:|---|
| 音乐库主标题 | 28sp | Bold |
| 普通页面标题 | 20sp | Medium，保持紧凑 |
| 首页/列表分区标题 | 18sp | SemiBold/Bold |
| 音乐库分类行标题 | 18sp | Normal/Medium |
| 迷你播放器曲名 | 16sp | Medium，单行 |
| 次要说明/副标题 | 14sp | Normal，使用次级文字色 |
| 底部导航标签 | 12sp | 选中态 Medium，未选中态 Normal |
| 辅助说明 | 12–14sp | 可读优先，不用低对比度灰色 |

所有文本允许系统字号缩放。超长标题按组件规则省略，不能通过缩小字体维持单行，也不能让标题变化导致相邻组件跳动。

## 5. 根导航与 App Shell

### 5.1 四个根入口

按既有产品合同固定顺序：
1. 主页
2. 搜索
3. 音乐库
4. 设置

| 属性 | 视觉规格 |
|---|---|
| 位置 | 底部固定导航，位于迷你播放器下方 |
| 总高度 | 内容区 60–64dp；系统底部手势/inset 另行处理 |
| 分栏 | 四项等宽，图标与标签垂直排列并居中 |
| 图标 | 24dp，采用清晰、简洁、笔画一致的 Material/原生线性图标风格；可参考截图的语义，不复制专有品牌资产 |
| 标签 | 12sp，单行居中 |
| 选中态 | 图标使用当前主题品牌强调色或对比度安全的变体；标签使用达到文字对比度目标的橙色语义变体，图形可使用更实的填充/选中变体 |
| 未选中态 | 中性灰色，不与禁用态混淆 |
| 触控 | 每项完整热区至少 48dp 高；触摸反馈轻量，不缩放整个导航栏 |
| 状态 | 选中态与当前根路由一致；切换根入口不得重建 AppRuntime 或清除未解决操作 |

主页使用房屋/主页语义图标，搜索使用放大镜，音乐库使用音乐/资料库语义图标，设置使用齿轮。不得增加“新发现”“广播”等额外根入口。

### 5.2 AppBar

- 常规页面使用紧凑标题栏，左侧/起始位置为当前页面标题；右侧保留全局状态环入口。
- **不设置全局三点溢出菜单**；应用设置通过独立的“设置”根页面进入。
- 不把状态环画成 Android 系统状态栏图标，不覆盖挖孔、时间、通知或系统手势区域。
- 音乐库顶层标题可比普通页面标题更大；其下直接进入分类列表，不增加“最近添加”模块。
- 全屏播放器是独立目的地，隐藏根底部导航和迷你播放器；由播放器任务进一步细化其完整布局。

## 6. 迷你播放器

迷你播放器参考用户截图的固定横条比例，位于正文与底部导航之间，是正常布局节点，不覆盖内容。

| 属性 | 冻结值/规则 |
|---|---|
| 内容区高度 | 64dp（系统 inset 不计入） |
| 顶部分隔 | 1dp 中性分隔线 |
| 封面/占位图 | 48×48dp，圆角约 6dp；左侧内边距约 8dp |
| 曲名 | 16sp，单行省略号；只显示标题，不显示艺术家 |
| 主按钮热区 | 至少 48×48dp，靠右放置，保持固定位置 |
| 控件范围 | 封面、曲名、单一播放/暂停按钮；不显示进度条、上一首、下一首、歌词或输出信息 |
| 无曲目 | 使用无曲目占位图与明确空状态；不得虚构歌曲名称 |
| stale/unknown/断线 | 最后已知曲目若存在可保留展示，但要标示未确认状态；播放/暂停真实禁用 |
| 几何稳定 | 曲名长度、封面有无、状态切换不得改变栏高、按钮位置或挤压底部导航 |

点击迷你播放器主体进入全屏播放器；点击播放/暂停按钮不能触发导航。在 Task 3，播放/暂停控件必须真实禁用，不发起 mutation；之后由播放器业务任务在复用既有协调器与真实播放观察后接入。

迷你播放器只在主页、搜索、音乐库显示；设置页隐藏，但设置页仍有 AppBar、全局状态入口与底部导航。

## 7. 音乐库入口列表

### 7.1 页面结构

使用截图中的清晰列表风格：较大的“音乐库”主标题、纵向分类列表、每行一个轻量图标与标题、细分隔线。**不显示“最近添加”模块或任何曲目/专辑网格推荐。**

初始分类入口按以下顺序呈现：
1. 播放列表
2. 艺人
3. 专辑
4. 歌曲
5. 流派/风格
6. 年代
7. 标签
8. 收藏

这保留产品总规格所要求的曲库覆盖范围；前四项顺序贴近参考截图，其余入口按相同列表样式继续排列。类别未接入真实数据时可进入明确的占位状态，但不能显示伪造的计数、封面或资源名称。

### 7.2 分类行

| 属性 | 冻结值/规则 |
|---|---|
| 最小行高 | 56dp；空间不足时可扩大，不能低于 48dp 触控目标 |
| 前导图标 | 24dp，使用简洁、一致的语义图标；图标色使用主题强调色 |
| 行标题 | 18sp，主文字色 |
| 左右内边距 | 16–20dp |
| 分隔线 | 1dp；从文字列之前的统一缩进位置开始，不贯穿整行图标列 |
| 交互反馈 | 整行可点击，焦点/无障碍描述正确，不只依靠图标表达含义 |
| 行状态 | 选中/加载/空数据状态不产生突兀高度跳变 |

播放列表、艺人、专辑和歌曲应采用易辨认且风格统一的图标语义。可参考截图的音乐列表、麦克风、专辑/容器、音符意象；不要复用图片中的专有素材。收藏、流派、年代、标签采用对应的原生语义图标。

“编辑”按钮只在后续产品合同明确存在真实编辑行为时出现；Task 3 不放置无法工作的装饰性操作入口。

## 8. 主页占位结构

主页不照抄 Apple Music 的推荐页，不引入截图中的“音乐新发现”、C-Pop、个性化推荐横滑卡片或专辑图等内容。

Task 3 仅建立主页页面容器和未来模块的布局槽位：
- 标题栏“主页”；
- 正文可滚动容器；
- 预留未来模块的纵向间距与内容区域；
- 在尚无真实模块数据时使用克制、清晰的空/占位状态，不填充虚构曲目、封面、播放历史、推荐内容或假操作按钮。

占位容器不能误导用户认为推荐、最近播放、歌单或服务端读取已工作。真实模块顺序、数据映射、刷新与空/错误状态由后续主页业务任务冻结；Task 3 只负责尺寸稳定、滚动、安全区以及与迷你播放器/底部导航的布局关系。

## 9. 集合/列表操作的视觉合同

本节记录后续业务页面必须采用的统一视觉位置与既有 Web 行为映射；**不扩大 Task 3 的产品实现范围**。Task 3 仅实现 App Shell、基础页面容器和预留布局，不实现歌曲数据读取、集合操作或真实播放请求。

### 9.1 集合级“全部播放”和“随机播放”

任何呈现多首歌曲的语义集合/列表都必须提供集合级：
- 全部播放（Play All）
- 随机播放（Shuffle）

适用范围包括全部歌曲、专辑、艺人、流派/风格、年代、标签、歌单、收藏、搜索返回的歌曲集合，以及未来主页中真正展示的曲目集合。不得把此要求实现为每一首单曲的重复菜单选项。

视觉位置：放在集合详情/列表的标题区域或列表头部的统一操作区，位于歌曲行之前。两个操作都必须有清晰文字或可访问标签，触控目标至少 48dp；在窄屏允许使用稳定的图标+文字或菜单收纳形式，但不应隐藏其中一个操作。主次样式须遵循现有橙色主题，不能用视觉样式暗示操作已成功。

行为：沿用现有 Web 与 CollectionRequest 的集合来源、随机选择、排序、不可用成员、Playback Context 和服务端队列规则。Android 不本地拼队列、不自行随机打乱 song IDs、不为“随机播放”新建业务算法。操作结果与同步状态由共享 Runtime/协调器和服务端回执决定。视觉入口在每个歌曲集合/列表中统一提供；如果某一来源目前没有现成的可见入口，应复用既有集合请求和 Web 行为语义补齐 Android 入口，不得为此另造服务端播放逻辑。若服务端明确拒绝/不支持某个来源，应如实显示不可用/不支持，不得静默假装操作成功。

### 9.2 全部歌曲列表的排序

音乐库的“歌曲”子列表必须有清晰、可发现的排序按钮，放在歌曲列表标题/操作行右侧，触控热区至少 48dp；图标建议使用简洁的排序/上下箭头语义，不增加浮夸装饰。

根据现有 API 合同，全部歌曲列表可支持：
- 排序字段：标题（`title`）、修改时间（`modified_at`）；
- 排序方向：升序（`asc`）、降序（`desc`）。

排序 UI 应让用户看得出当前字段与方向，并通过既有 Web/API 语义发起排序、读取/展示服务端结果。不得另造本地排序优先级、增加合同未定义的排序字段，或在页面内重排后把本地结果冒充服务端权威。其它集合的排序选项沿用其 Web 现有行为，不从全部歌曲列表推导出全站统一新规则。

### 9.3 单曲操作菜单

每首歌曲自己的操作菜单继续沿用 Web 已有菜单、动作范围与调用语义。不得重新设计另一套单曲逻辑，也不得为了本节的集合级播放入口把“全部播放/随机播放”机械添加到每首单曲的菜单里。新增菜单项需有明确的 Web/API 合同证据，不允许先放置不可执行的按钮。

### 9.4 与 Task 3 的边界

- Task 3 可以冻结未来集合工具栏和排序入口的视觉位置，但不实现真实集合数据与播放 mutation。
- Task 3 迷你播放器的播放/暂停继续保持真实禁用。
- 集合级播放/随机播放、歌曲列表排序、单曲菜单在各自业务 Task 中接入现有 Repository、共享 MutationCoordinator 和 API；不得创建第二个 Runtime/状态源。
- 真实服务端联调仍受 Task 2 未完成的 mutation/readback 和 APK live-origin 门槛约束。

## 10. 全局状态环与活动详情

### 10.1 位置与形状

- 状态环属于应用窗口内部的全局 UI，不是跨应用悬浮窗，不申请悬浮窗权限。
- 默认锚定在紧凑 AppBar 的右侧，代替全局三点菜单位置；在所有根页面保持一致，全屏目的地按其布局保留可达的状态入口。
- 默认可见圆环直径 36dp、线宽 3dp；实际触控热区 48×48dp。圆环图形可小于热区，不能缩小可操作区域。
- 在状态详情打开时保留其来源状态并提供明确关闭入口；不得让状态环遮盖标题、系统安全区或正文操作。
- 优先使用简单圆环/弧段与少量状态符号，不加厚重外框、浮夸发光或无业务意义的装饰。

### 10.2 默认语义与状态优先级

状态环仅是共享连接、snapshot freshness、observation 与 OperationActivity 的视觉投影；不能作为新的状态来源。视觉冲突时按以下顺序选取摘要状态：
1. 未解决操作的结果未知（UNKNOWN）或明确失败（FAILED）；
2. 尚在进行的操作（PENDING/SYNCING）；
3. 已知断线、snapshot stale/unknown 或播放观察未确认；
4. 最近完成的成功/信息提示（短暂显示，不得掩盖 1–3 项）；
5. 无未解决活动且连接/快照状态可用时的常态。

具体表现：
- PENDING/SYNCING：使用主题橙色环与克制的旋转/进度表现，并提供“正在处理”等可访问语义。
- UNKNOWN/FAILED：使用错误语义颜色及明确符号/缺口或形状差异，并通过详情文字区分“结果未知”与“明确失败”。
- DISCONNECTED/STALE/UNKNOWN freshness：使用中性/警示语义和不完整环形或对应符号，明确表示“未连接/状态未确认”，不能呈现连接成功。
- SUCCESS/INFO：使用短暂、低干扰的确认反馈；不保留永久成功色来掩盖当前连接/freshness 状态。
- IDLE/FRESH：使用低干扰的正常环形态。

颜色永远不是唯一的状态编码；必须结合符号、可访问性标签以及可打开的详情。任何状态变化都不能单凭圆环颜色令播放 controls 变为可操作。

### 10.3 环形动效

- 默认动效轻微，单次或循环反馈不干扰阅读；仅 PENDING/SYNCING 使用低幅度持续动画。
- 状态切换以短暂淡入/颜色过渡为主，建议 150–220ms；不使用弹跳、强烈缩放、闪烁、脉冲发光或大面积动效。
- 成功提示使用短暂的确认过渡，不无限循环。UNKNOWN/FAILED/断线不应持续抖动或闪烁。
- 动效不能成为理解状态的必要条件；动画被系统缩放关闭/受限时仍须完整表达状态。

### 10.4 用户可配置的本地选项

本地偏好项应归属于设置页的“状态环”分组，不发送到服务端：
- **直径：** 28–48dp，步进 4dp；默认 36dp。
- **线宽：** 2–5dp，步进 0.5dp；默认 3dp。
- **水平偏移：** 相对 AppBar 右侧默认锚点，范围 −24 至 +24dp，步进 4dp；默认 0dp。
- **垂直偏移：** 相对 AppBar 内容区域默认锚点，范围 −24 至 +24dp，步进 4dp；默认 0dp。

更改尺寸不得改变 48dp 最小触控热区；偏移不得让状态环进入系统状态栏/挖孔、安全区之外，遮挡重要控件或落到屏幕不可触区域。应用须提供恢复默认值的途径。设置控件/持久化的具体落地 Batch 由 Task 3 合同与后续设置任务范围决定；本规格冻结的是视觉参数与配置语义，不授权借机实现完整服务器设置表单。

## 11. 弹层、触摸和状态展示

- 弹层使用清晰标题、简短分组与轻量表面层次；点击外部/系统返回的关闭规则应符合 Android 常见习惯，关键状态详情提供明确关闭控件。
- 按钮、图标、列表行需有内容描述；关键状态不能只用颜色。触控目标至少 48dp，文字尊重系统字号。
- 禁用控件同时满足真实禁用和视觉灰化；不能只降低透明度却仍响应点击。
- 加载、空、错误、stale、unknown 是不同状态，使用正确文本/语义而非统一的灰色空白代替。
- 没有已接纳 snapshot 或真实播放观察未确认时，不能以绿色、勾选动画或“正在播放”等文案制造服务端已确认的错觉。
- 页面切换、内容变化和封面/占位内容切换保持布局稳定；避免 AppBar、正文、迷你播放器和底部导航的几何抖动。

## 13. 验收清单

### 视觉与布局
- [ ] 浅色、深色、跟随系统均保留品牌橙色系，文字/图标/边界对比度满足现有目标。
- [ ] 主页、搜索、音乐库、设置为仅有的四个根入口，顺序正确且图标/标签选中态一致。
- [ ] AppBar 紧凑，无全局三点菜单；状态环在 AppBar 右侧，不遮挡系统 UI。
- [ ] 音乐库包含播放列表、艺人、专辑、歌曲、流派、年代、标签、收藏入口；无“最近添加”区块。
- [ ] 主页仅显示结构占位，不显示假曲目、假封面、推荐或最近播放样例数据。
- [ ] 迷你播放器高度/封面/标题位置稳定，只有曲名与必要控件，无艺人文字、进度条或额外下一首控件。
- [ ] 设置页隐藏迷你播放器，但保留根导航与全局状态入口。
- [ ] 状态环的尺寸、线宽、位置偏移与语义优先级明确；详情可读且状态不靠颜色独立表达。
- [ ] 最小 48dp 热区、系统 Insets、大字体、窄屏/短屏与键盘布局通过目标设备检查。

### 行为边界与后续业务合同
- [ ] 每个歌曲集合/列表均有集合级全部播放、随机播放入口；其请求与播放编排沿用 Web/API 既有语义，不在客户端重复实现队列算法。
- [ ] 全部歌曲列表具备排序入口，支持 title/modified_at 与 asc/desc；排序通过既有服务端行为，不本地生成新顺序。
- [ ] 单曲菜单沿用现有 Web 操作，不新增一套单曲菜单逻辑。
- [ ] Task 3 不调用真实播放/暂停 mutation、不实现集合数据业务、不把 Task 2 的真实联调描述为已通过。
- [ ] UI 不创建新的 AppRuntime、SnapshotStore、RealtimeController、MutationCoordinator、socket 或业务状态持久化。
